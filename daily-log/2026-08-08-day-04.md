## 💡 Key takeaways (in my own words)

1. **The whole day in one sentence: an architecture with no path from a production failure back to a fix is not a production architecture.** The feedback loop is a structural component, not monitoring bolted on afterwards.

2. **Identity is an architecture concern, not an auth detail.** It's resolved at the *input* stage but it determines what retrieval may return three stages later. Deciding it late is how you get the service-account leak.

3. **Gates between steps are deterministic code, not model calls.** Using a model for a decision code can make is slower, costlier, and probabilistic exactly where a guarantee was needed.

4. **Draw the failure branch — half the marks live there.** Graceful degradation ("I couldn't determine this, routing you to a human") is a *successful* outcome. A confident fabrication is the failure mode that kills pilots.

5. **Every human override is free labelled data — but only if somewhere was designed for it to land.** Otherwise it evaporates into a support ticket. Traces (prompt version, model, tool calls + args + results, retrieval hits, tokens, cache hits, per-hop latency, `stop_reason`) are the prerequisite for Day 22's failure-attribution work.
