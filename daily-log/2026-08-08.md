## 💡 Key takeaways (in my own words)

1. **The dividing line isn't complexity — it's *who decides what happens next*.** You at design time (workflow) or the model at runtime (agentic). The practical test: **can I write the list of steps before the request arrives?**

2. **The agent loop:** gather context → decide → act → observe → repeat → **stop**. You can't know the path in advance because the path depends on what it finds.

3. **Over-engineering is the more expensive error.** A workflow chosen where an agent was needed is brittle and you patch it. An agent chosen where a workflow would do burns tokens, latency, and debuggability on *every request, forever*. That asymmetry is why the trap option is almost always the more autonomous one.

4. **They compose — this is the Professional-level answer.** "A workflow, with one agentic sub-step where the investigation is genuinely open-ended." You get predictability everywhere it's possible and pay for autonomy only where it's needed.

5. **Not everything in an LLM system should be an LLM call.** In the invoice example, "validate against the PO" is plain code. Spotting the deterministic step is part of the skill.
