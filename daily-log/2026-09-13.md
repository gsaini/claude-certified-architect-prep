## 💡 Key takeaways (in my own words)

1. **Day 3 picks *workflow*; Day 5 picks *which* workflow.** Each pattern has a characteristic failure: chaining without gates poisons downstream steps; routing is only as good as its classifier; parallelization breaks when subtasks aren't truly independent; orchestrator–workers is wasted when the subtask list was knowable; evaluator–optimizer loops forever without a concrete criterion.

2. **Parallelization vs. orchestrator–workers comes down to one question: when does the subtask list come into existence?** Known before the request arrives → parallelization. Decided by the model reading the task → orchestrator–workers. Everything else about them is the same.

3. **Routing is the first answer to a cost question.** If ~80% of traffic can take a Haiku path at ~1/5 of Opus's price: `0.8 × 0.2 + 0.2 × 1.0 = 0.36` → roughly **64% cheaper**, before caching, batching, or prompt work.

4. **Voting turns failure asymmetry into architecture.** Run a high-stakes judgement N times and act on majority *or* on any-flag — whichever matches the costlier error. Missing fraud costs more than a false alarm → flag if *any* run says fraud.

5. **They compose.** Routing → chains, with the hard branch handing off to an orchestrator whose workers each run a chain. A Professional-level answer names the pattern at each level.
